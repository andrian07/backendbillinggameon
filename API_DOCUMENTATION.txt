==================================================================
BILLING API - DOKUMENTASI ENDPOINT
==================================================================
Base URL   : http://localhost/billing_api/
Format     : {base_url}/{controller}/{function}
Content-Type default : application/json (body dikirim sebagai JSON di raw body)
Method default        : POST (kecuali disebutkan lain)

Semua response berbentuk JSON:
  { "code": 200, "result": ... }   -> sukses
  { "code": 0,   "result": "pesan error" } -> gagal
  { "code": 405, "result": "Method Not Allowed, gunakan POST" } -> method salah


==================================================================
SISTEM NOTIFIKASI & AUDIT (Api.php, history_hit_api_logs, history_query)
==================================================================

1) NOTIFIKASI KE SERVER PUSAT (application/libraries/Api.php)
--------------------------------------------------------------
HANYA action INSERT / EDIT / DELETE yang menyentuh 15 table berikut
yang memicu notify (scope dipersempit dari sebelumnya "semua
controller"): customer_point_history, customer_time,
customer_time_history, history_saldo, ms_customer, ms_payment (tidak
ada CRUD), ms_point_exchange, ms_product, ms_promo, ms_saldo,
transaction, transaction_cafe, transaction_cafe_detail,
transaksi_saldo, unit. Table lain (ms_role, ms_menu, role_access,
absensi, ms_user, ms_master_price, category, table_active,
keep_transaction, category_meja) TIDAK LAGI memicu notify.

URL dibentuk otomatis per aksi:
  {base_url}/{Module}/{function_name}

Contoh: module "billing", function "payment"
  -> http://localhost/gameon/Billing/payment
(base_url sekarang: http://localhost/gameon/ - server tujuan "gameon"
BELUM dibangun, ganti di application/libraries/Api.php properti
$base_url kalau alamatnya sudah pasti. Detail lengkap payload per
table ada di GAMEON_PAYLOAD_SPEC.txt)

Body yang DIKIRIM ke server tujuan adalah request body ASLI (flat,
field-nya sama persis seperti yang diterima endpoint aslinya) -
BUKAN dibungkus dalam struktur "data". Ini penting karena server
tujuan (gameon) menjalankan controller yang SAMA PERSIS dan
membaca field langsung dari root body.

6 table transaksional (customer_point_history, customer_time_history,
history_saldo, transaction, transaction_cafe, transaksi_saldo) juga
menyertakan field "branch" di payload - cabang milik user yang
melakukan aksi (dicari dari ms_user.user_branch lewat paid_by lalu
created_by, default 1). Lihat GAMEON_PAYLOAD_SPEC.txt section 5.

CATATAN: ID auto_increment hasil insert TIDAK PERNAH dikirim ke
gameon (notify bisa datang dari berbagai cabang dengan urutan
auto_increment masing-masing, jadi ID tidak dipaksa sinkron - gameon
generate ID sendiri sesuai data yang diterima). Lihat
GAMEON_PAYLOAD_SPEC.txt section 4.

CATATAN: field "password" dan "customer_pass" (plaintext) SEKARANG
IKUT DIKIRIM di notify add_user/edit_user/add_customer/edit_customer
(sebelumnya di-strip demi keamanan, sekarang sengaja dikirim atas
permintaan eksplisit supaya gameon bisa simpan sendiri). ms_user CRUD
sendiri sudah tidak lagi memicu notify (di luar 15 table), hanya
ms_customer (add_customer/edit_customer) yang masih relevan.

Pengecualian teknis: endpoint yang menerima multipart/form-data
(add_product, edit_product, add_point_exchange, edit_point_exchange)
- body notify dirakit manual dari field yang di-post (file gambar TIDAK
ikut dikirim). CATATAN: karena notify() selalu kirim Content-Type:
application/json sedangkan endpoint-endpoint ini di sisi server tujuan
membaca lewat $_POST (butuh multipart/form-data), replikasi otomatis ke
gameon untuk endpoint2 ini belum berfungsi penuh - field-nya
terkirim tapi tidak terbaca di sisi sana.

2) TRACKING STATUS UPLOAD PER ROW
--------------------------------------------------------------
Hampir semua table yang disentuh action insert/edit/delete di atas
punya kolom tambahan: {nama_table}_upload_status ENUM('Y','N') DEFAULT 'N'
- notify SUKSES (HTTP 2xx)                 -> kolom ini diubah jadi 'Y'
- notify GAGAL (curl error / HTTP non-2xx) -> tetap 'N'

3) HISTORY_HIT_API_LOGS (log setiap hit ke server pusat)
--------------------------------------------------------------
Setiap kali notify() dipanggil - SUKSES MAUPUN GAGAL - selalu dicatat
1 baris ke table history_hit_api_logs:
  module, action, function_name, status ('success'/'gagal'),
  endpoint_url, payload (body lengkap+konteks yang dikirim),
  ref_table, ref_id, http_code, response_message, created_at

4) HISTORY_QUERY (log semua query database - global, semua model)
--------------------------------------------------------------
Terpisah dari sistem di atas: SEMUA query database tulis
(INSERT/UPDATE/DELETE/REPLACE/TRUNCATE) yang dijalankan aplikasi -
dari model MANAPUN, tanpa perlu setting apapun per model - otomatis
tercatat ke table history_query lewat hook global (application/hooks/
query_logger.php, dipasang di application/config/hooks.php):
  query_text, query_type, table_name, status ('success'/'gagal'),
  execution_time, error_message, created_at
SELECT sengaja tidak dicatat (supaya table ini tidak cepat membengkak).

9. MAINTENANCE (Reset Data - BERBAHAYA/PERMANEN)
==================================================================

POST /maintenance/reset_data
Deskripsi : Reset SELURUH data transaksional (customer, product,
            transaction, absensi, purchase, dll) ke kosong. HANYA
            menyisakan data master/konfigurasi: category, category_meja,
            minute_setting, ms_master_price, ms_menu, ms_payment,
            ms_role, ms_saldo, ms_user, role_access, save_time_setting,
            unit. table_active TIDAK di-truncate, hanya kolom sesi
            booking-nya yang dikosongkan (table_customer_id,
            table_promo_id, table_mode, table_start_time, table_end_time,
            table_duration, table_bill, table_active -> semua direset/0).
            [DELETE]

            *** AKSI INI PERMANEN & TIDAK BISA DIBATALKAN ***
            Wajib kirim confirm: "RESET", kalau tidak akan ditolak.

Payload:
{ "confirm": "RESET" }

Response sukses:
{
  "code": 200,
  "result": "Seluruh data transaksional berhasil direset",
  "truncated_tables": ["absensi", "customer_point_history", "customer_time",
    "customer_time_history", "history_hit_api_logs", "history_query",
    "history_saldo", "keep_transaction", "keep_transaction_detail",
    "movement_stock", "ms_customer", "ms_point_exchange", "ms_product",
    "ms_promo", "purchase", "purchase_detail", "transaction",
    "transaction_cafe", "transaction_cafe_detail", "transaksi_saldo"]
}

Response ditolak (confirm tidak dikirim/salah):
{
  "code": 0,
  "result": "Aksi ini akan menghapus seluruh data transaksional secara permanen. Kirim confirm: \"RESET\" untuk melanjutkan."
}
